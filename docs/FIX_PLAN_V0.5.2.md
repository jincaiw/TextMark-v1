# TextMark v0.5.2 — 6 项问题评估与实施方案

> 状态：**已实施完成并全面测试通过**。浏览器实机（Chrome CDP，1440×900 与 760×760）验证：macOS 左预留 92px 无重叠、边栏下拉三项（隐藏边栏/大纲/文件夹）可见可用、打开方式与更多菜单可见、定制面板 16 卡片可点击添加、导出 PNG 35 万字节非空白（暗色模式同样非空白且主题正确还原）、PDF `%PDF-` 魔数正确。

## 1. 逐项根因评估

### 1.1 顶栏布局乱：边栏图标与窗口关闭/最小化按钮重叠；边栏右下角下拉（隐藏边栏/文件夹/大纲）不显示（问题 1）

三个叠加根因：

- **A（下拉不显示）**：v0.5.1 为防挤占给 `.native-actions` 加了 `overflow: hidden`（`src/App.css:80`）。工具栏所有下拉弹层（边栏菜单、打开方式、更多）都是 `position: absolute` 且位于工具栏**下方**的 `.menu-popover`，被该 `overflow: hidden` 直接裁掉 → 点开也看不见 → "不显示/没反应"。
- **B（与窗口按钮重叠）**：macOS 使用 `titleBarStyle: Overlay`，原生交通灯悬浮在工具栏左上 (18,20)，而 Tauri 下 `.window-leading { min-width: 0 }`（`App.css:408`）且没有预留左侧安全区。当用户自定义工具栏去掉了开头的"弹性空间"、或窄窗下弹性空间塌缩时，边栏图标滑到最左，正好压在交通灯上。
- **C（菜单项缺失）**：边栏下拉当前只有"大纲 / 文件夹"两项；上游为三项：**隐藏边栏 / 大纲 / 文件夹**（`DocumentWindowController.swift rebuildSidebarMenu`）。需补"隐藏边栏"。

### 1.2 "打开方式"下拉点击没反应（问题 2）

同 1.1-A：`.open-with` 的 `.menu-popover` 被 `.native-actions { overflow: hidden }` 裁剪，菜单实际打开了但不可见。

### 1.3 顶部拥挤；"三个点"点击没反应（问题 3）

- **点击没反应**：同 1.1-A（`.more-menu` 弹层被裁剪）。
- **拥挤**：溢出测量缺陷——`compute()` 用 `offsetWidth` 测量，但已隐藏项（`display:none`）宽度为 0 会被当作"放得下"，导致隐藏数量回弹为 0、所有项又挤回来；且宽窗时"更多"常驻 + 搜索框塌缩阈值（920px）偏晚。需修正测量（测量前先全部可见）、提前搜索塌缩（≤1180px 即折叠为图标）、默认保留弹性空间。

### 1.4 导出 PDF/PNG 为空白（问题 4）

v0.5.1 把导出改为"**离屏克隆 + html-to-image**"（`export.ts` `captureClonePng`：`position:fixed; left:-10000px` 的克隆节点）。在桌面 webview（WKWebView/WebView2）中该离屏组合渲染产空白 PNG，PDF 由空白 PNG 切片而来 → 同样空白。v0.5.0 的"活体根节点 + `toBlob`"路径本身可正常生成图像（当时坏在 `<a download>` 保存）。

**修复**：回归活体节点渲染（`.markdown-body` 直接 `toPng`，沿用 v0.5.0 的 filter 剔除拷贝按钮/HUD），暗色模式下**临时把 `data-theme` 切为 light 渲染后再还原**；PDF 复用该 PNG 按 A4 切片（保留现有多页逻辑）。实施时本地实机导出并核对文件非空白。

### 1.5 自定义工具栏像素级对标上游（问题 5）

现状差距与目标规格（依据上游 `DocumentWindowController.swift` 工具栏构建器 + AppKit 定制页）：

## 3. 验收标准

1. 边栏图标不再与交通灯/窗口按钮重叠；边栏下拉可见且含**隐藏边栏/大纲/文件夹**三项并可用。
2. "打开方式"与"更多"下拉正常弹出、可点选。
3. 窄窗（760px）工具栏无挤占：溢出项进"更多"菜单，弹性空间正常塌缩。
4. 导出 PNG/PDF 内容非空白（浅色模式 + 暗色模式均验证）；HTML 导出正常。
5. 工具栏与定制面板按上游规格逐像素截图对比通过（1440×900、760×760）。
6. 全量质量门绿；v0.5.2 经 CI 发布。

## 4. 决策结论

1. 版本按 **v0.5.2** 修复发布。
2. **定制面板版式：三平台统一 AppKit 版式**。评估理由：上游即为该版式（"全部一致"目标）；三平台统一可保证一处实现、行为一致、维护成本最低；且面板是可拖放的操作面板而非平台窗口，各平台用户均能接受 macOS 惯例（与本项目工具栏已采用的上游布局一致）。
3. **导出 PNG/PDF 固定浅色**（打印语义；暗色模式下也导出浅色），HTML 导出保持自包含浅色样式。
4. **发布流程**：实施完成后先做详细全面测试（本地 `tauri dev` 手动逐项验证 + `capture-ui` 双档截图对比 + 导出实机验证 + 全量质量门），全部通过后再经 CI 发布 v0.5.2。
