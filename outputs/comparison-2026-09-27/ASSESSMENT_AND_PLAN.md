# TextMark 0.10.27 与 Markdown Preview 0.0.62 对照验收与实施计划

日期：2026-09-27。基线为 GitHub 正式发布版 TextMark 0.10.27、Markdown Preview 0.0.62；测试文件为用户提供的 `MARKDOWN_RENDERING_TEST.md`（8,524 字节）。文档内容仅作为测试数据。参考应用源码固定在 `62274b1`，TextMark 源码固定在 `c777ced`。截图在 `screenshots/`，文件名前缀为取证顺序。

## 方法与界限

在同一台 Retina Mac 上安装并打开两个正式发布包，用同一份文件查看预览与编辑模式，通过原生可访问性树确认控件和文档结构。截图保留原始窗口尺寸，因两应用窗口宽度不同，不能将像素差直接视为排版缺陷。源代码和既有功能矩阵用于补全功能清单；未操作的功能在下表明确标记为待验证。Windows/Linux 无本轮实机，不能推断其视觉一致性。

## 实施顺序与验收条件

1. **P1 文件导航**：打开单个本地文件时自动展示其父目录并选中文件，保留 `[TOC]` 自动生成。验收：文件夹边栏非空且选中文件。
2. **P1 编辑切换与顶部布局**：预览/编辑起点已修复；960 CSS px（760 px 原生窗口）回归确认顶部动作和搜索输入可见、有序、不重叠。半屏实机鼠标缩放未成功，不作为已通过的手动检查。
3. **功能交互矩阵**：更新了过时的 E2E 假设，使边栏直接模式选择、外观面板缩放和“无历史时隐藏导航”与当前 UI 一致；桌面 Shell E2E 22 项全过。部分复杂格式、自定义工具栏、主题变体和各导出类型没有逐项人工操作，留在发布后补充矩阵。
4. **更新与发布回归**：真实 Tauri Rust 命令成功读取线上清单；发布工作流会校验六类更新目标及资产签名。0.10.26→0.10.27 安装并重启后的报错无法在当前环境重现，0.10.27→0.10.28 的真实覆盖升级应作为本次发布后的第一项验收。

## 本轮实施与验证记录

- `src/hooks/useDocument.ts`：单文件打开时以父目录初始化文件夹侧栏；在自动目录模式中打开其他文件夹的文件会跟随切换，手动打开工作区会锁定用户选择，并通过请求序号防止过期扫描回写。候选 macOS `.app` 实机打开本测试文件后，AX 显示 Downloads 与该文件，截图 09；修复前截图 04 为边栏空态。
- `src/App.tsx`：预览位置处于首个标题之前时，以源码第 1 行进入编辑模式；返回预览时恢复文档顶部。候选 `.app` 实机进入编辑模式后 AX 为 Line 1, column 1，截图 10 可见 frontmatter、`[TOC]` 与标题。
- `src/components/Sidebar.tsx`：当前文件在长文件列表中时，滚动文件夹边栏让选中项可见。候选 `.app` 实机截图 11 显示活动文件已高亮且在边栏可见。
- `src/App.css`、`src/preview-host.css`：修正 `==...==` 的黄色高亮，并保持预览和独立 HTML 导出一致。根因为引用了未定义的 CSS 变量；截图 07、08 显示修复前差异，截图 12 验证候选包黄色高亮。
- 完整前端测试：51 个测试文件、445 项通过。`npm run build`、`npm run lint`、`npm run format:check`、`npm run check:bundle`、Rust 25 项测试、Clippy 均通过。
- 出口回归 `npm run test:exports` 通过：生成完整 HTML、PNG 与 PDF；HTML 内容高度 2038 px，检查到 6 个标题、2 张表、2 个任务项、数学公式和 Mermaid 图，无脚本、内联事件、失败网络请求或浏览器错误；PNG/PDF 文件头有效。
- Tauri updater 运行时回归通过：候选应用调用真实 `check_update_channel(stable)` 从 GitHub 读取 0.10.27 清单，并返回当前版本最新。候选 `.app` 本地打包没有签名密钥，因而不能制作可安装更新包；正式发布 Workflow 的 GitHub Secrets 则已在 v0.10.27 全平台签名与上传任务中成功使用。
- RustSec `cargo audit` 退出码为 0，报告 7 条已允许的维护/安全提示；其中 Linux GTK 传递依赖 `glib 0.18.5` 命中 RUSTSEC-2024-0429（INFO / Unsound，受影响 API 为 `VariantStrIter`，修复版从 `glib 0.20.0` 起）。TextMark 没有直接依赖/调用该迭代器，当前 GTK/Tauri 锁定链尚未升级到 GLib 0.20；保留为 Linux 依赖维护项，不隐藏审计结果。
- 候选 `.app` 查找 “Markdown” 得到 13 项；连续点 6 次“下一个”从 1/13 到 7/13，查找栏始终可见（截图 13）。替换栏可展开和收起，完成按钮关闭查找栏（截图 14）。此项只在当前宽窗口复核，半屏窗口尚未复核。
- 候选 `.app` 用原生导出操作生成 `MARKDOWN_RENDERING_TEST-candidate.html`（约 1.6 MB）。静态结构检查确认包含最后一节“14. 任务核对清单”、末尾脚注、`<mark>重点内容</mark>` 及黄色高亮样式，不再只有上半部分；本轮不能通过浏览器以 `file:` 视觉打开，完整文件结构检查通过，视觉滚动到底仍待补验。
- macOS 桌面布局 E2E 首次发现测试断言落后于产品：原生标签栏常显却断言不存在。更新为平台条件断言，并新增 760 px 窄窗控件顺序和搜索可见性校验，布局套件 3 项通过。桌面 Shell E2E 的旧选择器已按当前直接边栏模式、外观面板缩放和条件导航行为修正；使用隔离临时配置目录执行的完整 22 项通过。重复复用临时配置时曾出现 dirty 标记等待超时，隔离后用例通过，测试环境已清理。

仍未验证的范围：Windows/Linux 本轮无实机；安装/卸载/跨版本覆盖升级未完整执行；本机手工拖动窗口未成功，但 760 px 原生窗口几何 E2E 通过；HTML 导出未在浏览器完整视觉滚动验证；工具栏自定义全部排列、主题组合、所有导出格式及所有编辑格式工具未逐项人工覆盖。运行时清单检查不等于实际安装成功。Linux 依赖审计还有上述 7 条 allowed warnings（含 glib unsound notice），后续需随 Tauri/GTK 依赖升级消解。它们不应被报告为“完全一致”。
